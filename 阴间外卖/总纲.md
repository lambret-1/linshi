

# 《超时扣款，阴间催单》总纲：五纲调度管理与文件结构树

**第一部分：五纲调度规则**

## 一、五纲调度规则

### 1.1 调用关系图

```
主线纲（P0）
  ├──→ 卷纲（P1）
  │      └──→ 章纲（P3）
  ├──→ 人物纲（P1）
  │      └──→ 章纲（P3）
  └──→ 支线纲（P2）
         └──→ 章纲（P3）
```

> **核心原则**：上游纲约束下游纲，下游纲不得反向修改上游纲。所有修改必须自上而下级联。

### 1.2 级联更新规则表

| 修改源 | 直接影响 | 间接影响 | 更新操作 |
| :--- | :--- | :--- | :--- |
| 主线纲 | 卷纲、人物纲、支线纲 | 章纲 | 重审所有下游纲的阶段目标/情绪曲线/角色弧光 |
| 卷纲 | 章纲 | 支线纲嵌入点 | 重拆受影响单元的章纲任务 |
| 人物纲 | 章纲 | 支线纲关系线 | 更新受影响章节的角色任务/对话/身体描写 |
| 支线纲 | 章纲 | 无 | 更新受影响章节的支线标注/字数占比 |
| 章纲 | 无 | 无 | 仅更新本章，不回溯上游 |

### 1.3 优先级裁定表（P0-P4）

| 优先级 | 来源 | 裁定规则 | 典型冲突场景 |
| :--- | :--- | :--- | :--- |
| **P0** | 主线纲·核心冲突/结局走向 | 不可违背，任何下游纲与之冲突时必须让步 | 卷纲节奏与主线阶段目标矛盾 |
| **P1** | 主线纲·角色认知档案 / 人物纲·S级设定 | 角色行为必须符合当前认知层级，情节为角色服务 | 章纲任务要求角色做出不符合认知的选择 |
| **P2** | 卷纲·情绪曲线 / 支线纲·自驱目标 | 情绪节奏优先于单章爽点；支线独立性优先于主线便利 | 章纲爽点破坏卷级情绪铺垫 |
| **P3** | 章纲·钩子/埋点配置 | 钩子类型/位置/绑定关系在章级锁定 | 正文写作时发现更好的钩子方案 |
| **P4** | 正文·语言/细节/节奏微调 | 在不违反P0-P3前提下自由发挥 | 正文发现更自然的对话表达 |

> **特殊场景裁定**：
> - 角色vs剧情：P1 > P2，永远让情节适应角色，而非角色适应情节
> - 支线vs节奏：P2内部协商，若无法协调则支线降级为背景级
> - 钩子vs反AI味：P3与反AI味规范平级，冲突时优先保反AI味

### 1.4 跨纲一致性校验机制

| 触发时机 | 检查内容 | 发现问题处理 |
| :--- | :--- | :--- |
| 每完成一卷章纲 | 章纲任务是否覆盖卷纲所有目标；角色行为是否符合人物纲当前状态；支线嵌入是否符合支线纲活跃度矩阵 | 回溯修正章纲，记录偏差原因 |
| 每完成一个阶段（50章） | S级角色认知变化是否与主线纲节点对齐；埋点回收率是否达标；钩子类型分布是否均衡 | 召开"阶段审查会"，批量修正并更新追踪表 |
| 每次修改上游纲后 | 所有受影响的下游纲是否已同步更新 | 按级联更新规则表逐项执行，未完成前禁止继续创作 |
| 正文写作中发现偏差 | 正文是否偏离章纲P0-P3约束 | 记录偏差→评估是否需要回溯修改章纲→更新版本 |
| 每10卷深度审查 | 五纲整体是否仍自洽；是否有累积性偏移 | 全面审查+总纲更新 |
| 读者反馈触发 | 外部反馈是否揭示内部未发现的矛盾 | 评估反馈有效性→决定是否触发上游纲修订 |

## 二、创作工作流管理

### 2.1 六阶段划分

| 阶段 | 核心任务 | 输入 | 输出 | Gate检查节点 |
| :--- | :--- | :--- | :--- | :--- |
| **①大纲期** | 确立故事内核与全局规则 | 创意灵感/题材调研 | 主线纲v1.0 + 人物纲v1.0 | 抓注意力摘要通过五项检查；角色认知六层自洽 |
| **②卷纲期** | 规划50卷节奏与结构 | 主线纲+人物纲 | 卷纲v1.0 + 支线纲v1.0 | 50卷总览表完整；防重复策略验证通过 |
| **③章纲期** | 细化单章执行方案 | 卷纲+支线纲+人物纲 | 章纲v1.0（分批） | 每批10章通过三层质量检查 |
| **④试写期** | 验证体系实操性 | 前3章章纲 | 前3章正文定稿 + 体系修订记录 | 前100字留人测试通过；反AI味过筛通过 |
| **⑤量产期** | 批量创作正文 | 章纲+已验证体系 | 正文草稿→定稿（持续） | 每卷Gate检查+进度追踪更新 |
| **⑥修订期** | 全书统稿与优化 | 全部定稿 | 终稿 + 修订日志 | 跨卷一致性审查通过；埋点100%回收 |

### 3.2 文件命名规范

| 文件类型 | 命名格式 | 示例 |
| :--- | :--- | :--- |
| 大纲文件 | `[纲类型]_outline.md` | `novel_outline.md` |
| 章纲文件 | `vol[两位卷号]_ch[三位起始章]-[三位结束章].md` | `vol01_ch001-040.md` |
| 正文草稿 | `ch[三位章号]_v[版本号]_draft.md` | `ch001_v1.0_draft.md` |
| 正文定稿 | `ch[三位章号]_final.md` | `ch001_final.md` |
| 素材文件 | `[功能描述].md` | `hook_library.md` |
| 日志文件 | `[日志类型]_log.md` | `revision_log.md` |
| 归档文件夹 | `v[版本号]_archive_[YYYYMMDD]/` | `v1.0_archive_20260101/` |
| 修订版本 | `_v[主版本].[次版本]` | `_v1.1`（小修）/ `_v2.0`（大改） |

### 3.3 正文草稿→定稿流转条件

草稿转为定稿必须满足以下全部条件：
- [ ] 通过单章完成度检查清单（7大类20+项）
- [ ] 通过反AI味过筛（T1禁用词/最毒句式/感官锚点）
- [ ] 章纲P0-P3约束未被违反（或已记录偏差并获批准）
- [ ] 所属单元的单元级检查通过
- [ ] 版本号标记为`_final`并从drafts/移至final/

### 3.4 备份与归档策略

| 备份类型 | 触发条件 | 存储位置 | 保留周期 |
| :--- | :--- | :--- | :--- |
| 日常备份 | 每日创作结束后 | 本地+云盘 | 30天滚动 |
| 里程碑归档 | 每完成一个阶段 | archive/ | 永久 |
| 版本快照 | 每次上游纲重大修改前 | archive/ | 永久 |
| 发布备份 | 每次向平台提交前 | exports/ + 外部存储 | 永久 |

## 五、总纲自维护规则

### 5.1 更新触发条件

| 触发条件 | 更新内容 | 紧急度 |
| :--- | :--- | :--- |
| 主线纲重大修改（核心冲突/结局变更） | 级联更新规则表+优先级裁定表 | 立即 |
| 新增/删除纲层级 | 调用关系图+文件结构树 | 立即 |
| 工作流阶段调整 | 阶段划分表+Gate检查节点 | 本周内 |
| 文件命名规范变更 | 命名规范表+已有文件重命名 | 本周内 |
| 产物清单变化 | 已生成/待生成清单+依赖关系图 | 下次更新时 |
| 每完成一个阶段 | 全量审查+版本号递增 | 阶段结束时 |
| 外部反馈揭示体系缺陷 | 对应模块修订+修订日志记录 | 评估后决定 |

### 5.2 总纲与五纲的同步机制

- **单向约束**：总纲约束五纲的管理方式，但不干预五纲的内容创作
- **同步方向**：五纲内容变更 → 触发总纲审查 → 总纲决定是否更新
- **禁止反向**：总纲不得直接修改五纲内容；如需修改，必须通过五纲自身的修订流程

### 5.3 版本管理

| 版本类型 | 格式 | 触发条件 | 示例 |
| :--- | :--- | :--- | :--- |
| 主版本 | vX.0 | 结构性变更（新增纲层级/工作流重构/目录结构大改） | v1.0 → v2.0 |
| 次版本 | vX.Y | 内容修订（规则调整/清单更新/命名规范微调） | v1.0 → v1.1 |
| 补丁版本 | vX.Y.Z | 勘误/笔误修正 | v1.1 → v1.1.1 |

> **版本记录**：每次更新必须在总纲末尾追加版本变更记录表。
